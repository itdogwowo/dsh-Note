# 還沒解的問題 / 想做的事

> 這裡放「知道有問題但還沒處理」和「想做的工具」。
> 解決了就搬去對應的子系統文件，並在 [`pitfalls.md`](pitfalls.md) 留一條。

## 未解

### 技能的觸發是機率性的

[`skills.md`](skills.md) 說明了：觸發條件就是 description 的自然語言，由模型每輪自己判斷。
**沒有任何系統會「保證」觸發。**

想要確定性觸發的話，要離開技能系統，改用：

- system prompt section 的動態 `text: (ctx) => …`
- `agent/pre-step` waterfall（在每一輪模型請求前跑，可以依訊息內容決定要不要注入）

### 兩份技能副本會漂移

`~/.dsh/skills` 和別的工具（例如 `~/.trae/skills`）是**兩份獨立副本**，
改一邊不會同步另一邊。目錄連結是一個選項，但各平台的 git 行為不一致。

### 世界書只掃「進來的那則訊息」

不是「最近 N 則」。所以關鍵字只出現在更早的對話裡時不會命中。

### 這個 repo 還沒有同步工具

目前是手動複製（見 [`sync.md`](sync.md)）。想做的：

```
tools/export.mjs    ~/.dsh → repo，匯出前自動掃洩漏
tools/apply.mjs     repo → ~/.dsh，先備份、支援 --dry
tools/doctor.mjs    檢查缺漏、洩漏、兩台機器的差異
```

**寫之前先手動用一陣子**，看流程哪裡真的卡，再決定工具要長什麼樣。

## 想做的

### 確定性觸發的技能掛鉤

如果技能可以宣告觸發詞，然後由一個 `agent/pre-step` 掛鉤比對訊息、命中就注入
`<skill_content>`，那 `whenToUse` 就從裝飾品變成真的觸發條件。

### 筆記的搜尋

`notes/` 長大之後會需要。目前靠 `grep`。

## 已知但決定不做

| 項目 | 為什麼不做 |
|---|---|
| 同步 `sessions/` 與 `attachments/` | 上百 MB，而且隱私風險高於價值 |
| 同步 `pnpm-lock.yaml` | 體積換來的可重現性，在這個用量下不划算 |
| 目錄連結合併兩份技能副本 | 兩邊目錄結構會綁死，且 git 對連結各平台行為不一致 |
| 把 `AGENTS.md` 全搬進技能來省錢 | 實測只省 137 字／對話，是零錢不是省錢 |
