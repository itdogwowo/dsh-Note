# 公開 repo 的個資紅線

**前提：這些 repo 是公開的。** 下面每一條都是「寫下去的當下覺得沒什麼、
事後才發現公開了不該公開的東西」。

## 六條紅線

1. **不寫真實的使用者名稱或本機絕對路徑。**
   要寫路徑就用樣板：`C:\Users\<你的帳號>\…`、`/Users/<user>/…`、`~/.dsh/…`、
   `link:<你 clone 的位置>`、`<repo 的絕對路徑>`。

2. **不寫公司名、內部專案名、客戶名、同事名。**
   用「專案A」或 `<公司專案名>` 代替。
   ⚠️ **側邊欄的「工作區名稱」就是內部專案名**——它在畫面上看起來只是個標籤，
   所以你會忘了它算。

3. **不 commit 截圖。**
   截圖會連側邊欄一起拍進去（工作區名稱 ＋ 完整路徑）。**裁掉側邊欄，或改用文字描述。**
   ⚠️ **GitHub 網頁拖檔上傳不會看 `.gitignore`**——所以光靠 ignore 擋不住這條路。

4. **改完跑 `npm test`。** `verify.mjs` 有個資掃描（路徑形狀 ＋ 本地黑名單）會擋。

5. **講「上次洩漏了什麼」只講形狀，不講內容。**
   解釋「為什麼要防這個」的時候最容易順手把要防的字串寫出來。
   真實發生過：在說明「為什麼黑名單比對要不分大小寫」的註解裡，
   直接寫出了公司名的實際大小寫——防線第一次跑就抓到作者自己。

6. **已經 commit 的洩漏，`force push` 沒有用。**
   GitHub 會繼續用 SHA 提供舊 commit 全文（實測回 **200 加完整 patch**，不是 404）。
   要嘛刪掉 repo 重建，要嘛寄 GitHub Support 要求清除不可達物件。

## 自己檢查

```powershell
# 掃目前的工作區
git grep -n '<關鍵字>'

# 掃整個歷史（-S 只找「新增或刪除」，搬移位置不會回報，要搭配逐版本掃）
git log --all -S'<關鍵字>' --oneline

# 那個 repo 的完整檢查
npm test
```

掃描範圍要記得涵蓋：`.md`／`.js`／`.mjs`／`.json`／`.yml`／`.txt`。

## 黑名單

`.privacy-denylist.txt`，**已 gitignore 的本機檔**，一行一個詞，`#` 是註解。
**黑名單本身就是機密**——不要 commit 它、也不要把它貼進對話或 issue。
每台機器要各建一份（macOS 和 Windows 各一）。
